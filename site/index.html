// The Problem

Every AI session starts
at zero.

You've had this conversation before. You've explained your stack, your preferences, your clients, your critical payload formats. Then the context window resets and you start from scratch. Again.

⚠

Amnesia by Default

LLMs have no persistent memory. Every session starts blank. Your agent doesn't know who you are, what you're building, or what mistakes to avoid. Context vanishes when the window closes.

⌛

Repeated Corrections

You told it not to use port 5173. You told it IntentCore uses "B2B" not true. You told it 970x250 is Tier 3. You'll tell it again tomorrow. And the day after that.

🚫

No Cross-Session Awareness

Agent A doesn't know what Agent B discovered. Last night's debugging session is invisible to this morning's feature build. Every agent is an island.

// The Architecture

Three layers. Zero cold starts.

Each layer serves a different time horizon and query type. Together, they give every AI agent full continuity across sessions, machines, and projects.

🗒

Layer 1: Auto Memory

File-based structured memory with YAML frontmatter. 64 markdown files indexed by MEMORY.md. Four types: user, feedback, project, reference. Loaded into every Claude Code session automatically.

  • YAML frontmatter (name, description, type)
  • MEMORY.md master index (37KB)
  • Staleness warnings on old memories
  • Cross-references via "See filename.md"
  • Auto-loaded on conversation start
🔎

Layer 2: Episodic Memory

Semantic search across every past Claude Code conversation. Full conversation archive with text and vector search. Restores decisions, solutions, and lessons from any prior session.

  • Semantic + text search across all sessions
  • Conversation archive with JSONL storage
  • Cross-project conversation recall
  • Superpowers plugin integration
  • "What did we discuss last week?" queries
🧠

Layer 3: Omni-Context

5-tier agent memory system purpose-built for the Orchestra. Priorities, facts, roadmaps, handoffs, and cross-project state. Every agent reads this on startup to know exactly where things stand.

  • context_layer.json (top-of-mind priorities)
  • facts_db.json (durable facts + retention scoring)
  • ROADMAP.md per project (authoritative status)
  • handoff.md (last session continuity)
  • Memory daemon extracts facts every 30 min

// Memory Types

Four types. Each with a job.

Not all knowledge is equal. The system classifies every memory by type so agents know what to trust, when to verify, and how to apply it.

👤

User

1 FILE

Who Shaw is, where he is, how he works. Location, timezone, communication preferences. Shapes every interaction to match the operator's context and expertise level.

💡

Feedback

13 FILES

Hard-won lessons and corrections. "Don't use port 5173." "IntentCore b2b is a string, not boolean." "970x250 is ONLY Tier 3." Each one prevents a repeated mistake and includes the reason why.

🚀

Project

21 FILES

Live state of every active project. Architecture, deployment endpoints, what's built vs. what's missing, P0 task lists, dependencies, blockers. The source of truth for "where are we?"

🔗

Reference

29 FILES

Pointers to external systems — Linear projects, Grafana dashboards, Obsidian notes, partner profiles, client details. Where to find information that lives outside the codebase.

Auto Memory Engine Complete

64 structured markdown files with YAML frontmatter, indexed by a 37KB MEMORY.md master document. Four memory types (user, feedback, project, reference) with automatic staleness warnings and cross-reference linking.

Episodic Recall Complete

Full conversation archive with semantic and text search via the Superpowers episodic-memory plugin. Query any prior session by topic, date, or content. Restores decisions, solutions, and debugging context across conversations.

Omni-Context 5-Tier Complete

Global priorities, durable facts with retention scoring, per-project ROADMAPs, session handoffs, and cross-project relationships. Memory daemon extracts facts from logs and Telegram every 30 minutes automatically.

Obsidian Knowledge Vault Complete

281+ notes organized by project in ~/ALL_CONTEXT/. Synced bi-directionally between Mac and VPS via Syncthing. Research, session logs, competitive analysis, roadmaps, and client documentation all interconnected.

Cross-Machine Sync Complete

Syncthing replaces rsync for real-time vault synchronization. Mac and VPS stay identical. Any agent on any machine reads the same ground truth. No conflicts, no stale state, no manual sync commands.

Mistake Prevention

Cross-Agent Continuity

The memory daemon syncs facts every 30 minutes. Agent A's discovery is Agent B's starting knowledge. No re-explaining. No information silos.

📊

Freshness Awareness

Every memory carries a timestamp. Memories older than 7 days trigger staleness warnings. The agent knows to verify before asserting stale state as current truth.
